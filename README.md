# AR ダンジョン（Android）

屋内の会場を歩き回りながらモンスターを集めて戦う AR ゲーム「AR ダンジョン」の Android アプリ（開発中）。
iOS アプリ（[jphacks/os_2609-iOS](https://github.com/jphacks/os_2609-iOS)）を移植している。プロダクト全体の説明は [jphacks/os_2609](https://github.com/jphacks/os_2609) の README にある。

## 製品概要
展示会や学園祭などの屋内イベントでは、来場者が入口付近や目当てのブースだけを見て帰ってしまい、会場全体を歩いてもらうのは難しい。
「AR ダンジョン」は、歩くこと自体を楽しくして、会場を回るきっかけを作る。屋内では GPS が届かないので、カメラで測る移動距離と、会場に置いた BLE ビーコンを使う。

### できること
* 最初に 3 体から相棒を 1 体選んでスタートする
* 会場を歩くと、カメラに映る床の上にモンスターが現れる（歩いた距離で出現するので、GPS がいらない）
* モンスターをタップするとバトルが始まる。画面をタップして攻撃し、スワイプで必殺技をよける。勝てば捕まえられる
* 目の前にいるプレイヤーと BLE で見つけ合い、その場でリアルタイムに対戦できる（iOS 版とも対戦できる）
* 会場マップで、自分が今どのあたりにいるかがわかる（会場に置いた BLE ビーコンの電波の強さから推定する）

### 特長
#### 1. 屋内でも、歩くほどモンスターに出会える
GPS を使わず、ARCore がカメラで測る端末の移動距離でモンスターを出すので、屋内のどこでも遊べる。
会場に置いた BLE ビーコンの電波の強さの組み合わせから、会場内のどのあたりにいるかも推定してマップに表示する。

#### 2. タップとスワイプだけで熱くなれる AR バトル
カメラに映る床の上で、3D のモンスター同士が戦う。画面をタップして攻撃し、必殺技の予告が出たらスワイプでよける。
攻撃しすぎるとスタミナが切れて休憩になり、フィーバーやチャンスの演出が駆け引きを生む。

#### 3. 目の前にいる人とだけ対戦できる
対戦の受付を ON にすると、近くの端末どうしが BLE で見つけ合い、一番近い相手が候補に出る。お互いが「対戦する」を選ぶと、サーバーがその 2 人だけを組み合わせる。iOS 版と同じしくみなので、OS が違っても目の前の相手と対戦できる。

### 注力したこと
* **iOS 版と同じ体験にそろえること**：同じ 16 体のモンスター、同じバトルのルールと数値、同じデータベースと近接対戦のしくみを使い、iOS 版とも対戦できるようにした
* **AR の画面を 1 つに保つこと**：捕獲画面の AR をバトル中もそのまま使い、床を探し直さずに、野生のモンスターがいた場所で戦う。AR とカメラ映像なしの 3D は同時に出さない

## 開発技術
### API・データ
* Supabase（supabase-kt）：マルチバトル。近くの相手の確保と双方の承諾、対戦の部屋づくりは Postgres の関数（RPC）、攻撃などのやり取りは Realtime の変更通知で送り合う。iOS 版と同じデータベースを使う
* Android の Bluetooth LE API：ビーコンの電波の強さ（RSSI）を受け取る。近くで対戦を受け付けている端末を見つける
* SharedPreferences：捕まえたモンスターとバトルに出すモンスターを端末に保存する

### フレームワーク・ライブラリ・モジュール
* Kotlin、Jetpack Compose、ARCore、SceneView（Filament）
* 3D モデル：Quaternius「Ultimate Monsters」（CC0 のフリー素材）。Blender のスクリプト（`scripts/convert_monster_models.py`）で GLB に変換している

### デバイス
* Android 端末（ARCore 対応機種、Android 7.0 以上）

## ビルド方法
1. Android Studio でこのフォルダを開く。Java 21 を使う（SceneView が使う kotlin-math が Java 21 向けのため）
2. 対戦の接続先：`local.properties` に Supabase の URL と anon キーを書く（コミットしない。書かなければ CPU が相手になる）

   ```properties
   supabase.url=https://xxxx.supabase.co
   supabase.anonKey=<anon（public）key>
   ```
3. 実機で実行する。エミュレータには ARCore がないので、AR とバトルは実機で確かめる

ビルドだけを確かめるときは次のコマンドを使う。

```sh
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew :app:assembleDebug
```
